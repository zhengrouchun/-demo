# 解决编号学习清单未显示为可勾选任务的问题

日期：2026-10-03。项目：`D:\语音转文字工具\LocalLecture`。

## 用户实际遇到的问题

“10.3学习要求”的正文是 `1.收到…`、`2.数码管…` 等编号内容，第 3 条甚至没有编号点。原任务解析严格遵守标准 Markdown `- [ ]` / `- [x]`，因此该笔记实际任务数为 0。

之前验证的是已经包含标准任务标记的笔记，漏测了用户现有的编号清单。大 Markdown 输入区域又把预览放在页面下方，手机截图中既没有转换入口，也看不到任务预览。这个实际使用场景没有被处理完整。

另发现手机 checkbox 独占一行：原通用 input 内边距叠加 flex 换行宽度，使 checkbox 与文字不能排在同一行。

## 解决流程

1. 用 GET /health 和 /api/state 确认正式服务已是学习任务版本，问题来自现有正文格式，不是后端未启动。
2. 读取真实 noteId、标题、正文、updated_at，确认有 7 条编号内容，metadata 为空；没有清空浏览器存储。
3. 沿用 markdownLines 的代码块保护，新增显式编号转换函数：只处理连续编号条目，保留条目文字、空行、换行格式及其他 Markdown。
4. 加入“编号列表转为任务（数量）”按钮和说明，点击后保存当前标题/正文并跳到预览；增加“添加任务”和“查看任务”入口。
5. 用用户原 7 条文本（包括第 3 条漏写点）作为回归输入，验证转换前 0 个任务，转换后恰好 7 个。
6. 将用户这份笔记原文单独保存到 JSON 备份；通过原 POST /api/notes 和 base_updated_at 版本校验，将这份指定笔记转换为标准任务。没有修改其他备忘录。
7. 核对条目、标题、noteId、原创建时间保留，7 个 UUID 独立、全部未完成；水滴余额仍为 23，其他流水、树、养胃、心情、语音记录和 timer 均未变化。
8. 手机任务行改为两列网格，checkbox 在文字前，同一行对齐；任务专注按钮显示在文字下方。
9. 在隔离数据中做转换、保存、刷新、原任务功能的完整浏览器回归，并用独立 Chrome profile 对正式 8876 页面做只读验证和截图。

## 阅读与修改文件

- `app/frontend/src/growmate/markdownTasks.ts`：阅读 markdownLines/setMarkdownTask；新增 numberedTaskConversion，返回转换后的正文和数量。代码围栏/缩进代码不会转换；日期版本号不会误识别为连续清单。
- `app/frontend/src/growmate/Records.tsx`：阅读 Notes 的草稿、save、withSaving、reconcileTasks 和预览；新增转换、添加任务及预览跳转操作，复用原 metadata 同步和保存接口。
- `app/frontend/src/growmate/GrowMate.css`：转换提示沿用原绿色风格；预览滚动留边；限定任务 checkbox 内边距和手机两列布局。
- `scripts/verify_note_tasks.cjs`：增加实际 7 条编号内容测试及代码/日期/版本/CRLF 保护测试，现为 13 项。
- `scripts/verify_learning_tasks_browser.py`：增加用户清单的一键转换、刷新后 UUID 保留、预览跳转和手机 checkbox 位置检查。
- `scripts/verify_numbered_note_live.py`（新增）：只读打开正式网页，验证这份具体笔记的正文、7 个 taskId、0/7 进度和手机对齐，输出实际截图。
- `docs/解决备忘录无法管理学习任务及联动专注奖励的问题.md`：补充本次编号清单转换修复的操作指引。
- 未修改后端、数据库表结构、录音、养胃、心情或桌宠模块；不需要新增 migration。

## 如何操作

这份“10.3学习要求”已经转换并保存，不需要再逐条改写。

1. 在现有网页按 **Ctrl+F5** 加载本次新界面。
2. 进入“记录 → 备忘录”，选择“10.3学习要求”。
3. 点击标题下方的 **查看任务（7）**，直接跳到任务和正文预览。
4. 预览里显示 7 个 checkbox、进度、筛选和专注按钮。点击 checkbox 后正文变成 x，保存并变淡加删除线；再次点击取消。
5. 以后粘贴编号学习清单时，点击 **编号列表转为任务（数量）**，会转换、保存并跳到预览。
6. 点击 **＋ 添加任务** 会在正文末尾添加任务模板并选中“新任务”，输入内容后保存。

普通编号列表不会静默变成任务；只有显式点击转换才改变正文。转换检测连续的编号组，兼容 `1.内容`、`1. 内容`、中文顿号、右括号以及组内漏写编号点的中文条目。孤立数字或日期不会自动转换。

## 方法与边界

使用显式转换修复已有文本的入口缺失，同时保持标准 Markdown 的识别规则；使用既有保存/API 而非增加第二套任务数据。先备份、使用版本校验、比较其他状态，避免覆盖并发正文或改动奖励。

代码解析复用 markdownLines；UI 跳转使用 scrollIntoView 并尊重减少动画设置；浏览器验证使用 Chrome DevTools 协议和隔离 profile。

本次转换后的任务均保持未完成，没有代用户勾选，没有为修复领取水滴。
