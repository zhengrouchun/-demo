# 解决语音转文字误删句子和遗漏尾音的问题

日期：2026-10-21。

## 问题与已确认的原因

本次修复的是代码中可以复现的漏句、尾音丢失和识别结果退化问题。系统日志另外存在 `data discontinuity in recording`，表示采音不连续；本次没有进行真实声卡的长时间采录，不能宣称硬件或系统层面的所有中断已经消失。

1. **把“需要核对”当成“必须删除”。** `session/manager.py` 的正常窗口和最后窗口原来只接收分类为 `keep` 的句子，`retry` 也被直接跳过。CPU 较忙时，保护机制会禁止重试，于是已经识别出的不确定句子消失。现在仅删除分类为 `drop` 的结果，其余结果保留并标记 `uncertain`。
2. **重试可能反而覆盖已有文字。** `_transcribe_window()` 原来直接使用重试返回值，即使它为空、质量更差，或者抛出异常。现在只有非空且质量评分不低于首轮的结果才替换首轮；失败时保留首轮文字。
3. **前置裁音缺少上下文。** GrowMate 原先在半秒音频上运行前置 VAD，再交给内部也启用 VAD 的 Whisper；前置检测未识别到的部分可能被裁掉，轻声补救又受负载保护限制。现在 GrowMate 保留连续波形，只在模型内部进行人声筛选。纯静音仍由能量门槛跳过，不会全部强行识别。
4. **结束标记可能挤掉末尾音频。** 音源自然结束且队列满时，旧代码可能先丢一块音频再插入结束标记。现在自然结束和正常停止均等待队列排空，保留尾音。
5. **采音失败未向上层传递。** Windows 录音线程原来只写日志，然后放入正常结束标记；设备格式错误也可能发生在重试范围外的上下文初始化阶段。现在在采样率重试内部真正打开设备，捕获失败后先交付已录音频，再向会话传递异常。
6. **错误提示和质量标记容易丢失。** 采音失败提示原来可能被下一次运行状态覆盖；拼接半句时也未保留质量标记。现在错误立即入库并随 Markdown 导出，拼接后保留较低质量的标记。

## 修复流程与方法

1. 使用 `rg` 搜索项目文件、参数、丢块及错误日志，用 `Get-Content` 阅读对应函数。读取最近录音记录确认使用系统声音、Small、中文；没有修改历史录音数据库内容。
2. 先运行现有真实 Whisper 离线检查，记录旧输出；再编写音频覆盖、尾音排空、不确定句子、重试退化、设备失败等回归测试。测试用临时数据库和模拟设备，不打开麦克风。
3. 将 GrowMate 的防漏句参数放入独立 `growmate/speech_coverage.py`，不堆入入口文件。项目是 Python/TypeScript 应用，因此按现有模块组织，没有新增 C 驱动或修改 CubeMX。
4. 顺序比较同一个本地样本。六秒候选方案曾出现模型断词及省略号输出，未采用；最终使用十秒上限，并允许积累至少两秒后在静音边界提前提交。这里的省略号来自模型输出，本次没有发现代码主动把完整原文截成省略号。
5. 识别线程从最多八个改成最多四个，同时保留至少一半逻辑处理器的余量；解码候选数从一个调整为三个。中文模式增加简体提示，自动/英文模式不附加中文提示。新增配置和关键修改均附中文作用说明。
6. 测试通过后确认服务没有活动录音，备份旧日志到 `data/before-speech-fix-时间戳-*`，通过正常关闭接口退出，再隐藏启动本地服务。健康检查返回 GrowMate，启动后处于空闲状态，两份原有录音记录仍在。

## 阅读和修改了哪些文件、哪些位置

以下路径均相对 `D:\语音转文字工具\LocalLecture`。

- `app/backend/meetingbro/growmate/speech_coverage.py`：新增 `model_options()`、`session_options()`，集中解释线程、候选数、连续窗口、轻声门槛和中文提示的用途。
- `app/backend/meetingbro/growmate/voice_worker.py`：模型创建与 `SessionConfig` 构造处改用上述配置；继续由短生命周期子进程持有模型和音频资源。
- `app/backend/meetingbro/session/manager.py`：修改普通/末尾结果过滤、`enqueue_end_sentinel()`、`_transcribe_window()`、`_consume_pending_segment()`。
- `app/backend/meetingbro/audio/loopback.py`：修改 Windows `_reader()` 的设备打开重试和异常传递，以及异步消费端的错误处理。
- `app/backend/meetingbro/growmate/voice.py`：`_event()`、新增 `_save_voice_warning()`；积压时明确提示还有多少秒音频待识别，完整性警告立即持久化。
- `app/backend/meetingbro/growmate/transcript.py`：`export_transcript()` 增加已记录异常的导出提示。
- `tests/test_speech_coverage.py`：新增八项回归测试。包括 11.5 秒轻声采样逐点一致、满队列自然结束、纯静音、低质量首轮/重试、半句合并标记、设备初始化回退及异常、持久警告与导出。
- `tests/test_growmate.py`：原进程测试样本由四秒改为十二秒，继续要求至少两段且覆盖最后两秒，适配更完整的音频窗口。
- `scripts/verify_speech_coverage_accuracy.py`：新增离线对照工具，使用当前调度器分别运行旧/新配置，输出文字、处理时间、丢块数和可选字符错误率。它比较的是配置，不是对旧源码的完整回滚复现。
- `data/benchmark/coverage_zh.txt`、`coverage_zh.wav`：中文合成测试原文及本地 SAPI 生成音频，不含用户录音。音频文件可能受现有 Git 忽略规则影响，可用下述命令重建。
- 还阅读了 `audio/vad.py` 的裁音与补边界逻辑、`audio/capture.py` 的采音队列、`audio/enhancement.py` 的音量调节、`asr/faster_whisper_adapter.py` 的 VAD 与解码参数、`audio/mixed.py` 的混音流程、`growmate/web.py` 的服务启停接口、前端 `growmate/Voice.tsx` 的质量提示。
- 核对了已安装 `soundcard/mediafoundation.py` 的 WASAPI 不连续警告来源，未修改第三方库或驱动。

## 使用的主要指令

在项目根目录运行：

```powershell
git status --short
rg -n 'drop|overflow|pre_vad|weak|retry' app/backend/meetingbro/session/manager.py
Get-Content data/growmate-web.err.log
git diff --check

.\app\backend\.venv\Scripts\python.exe -m unittest discover -s tests -p test_speech_coverage.py -v
.\app\backend\.venv\Scripts\python.exe -m unittest discover -s tests -p test_growmate.py -v
.\app\backend\.venv\Scripts\python.exe scripts\verify_stop_drain.py
.\app\backend\.venv\Scripts\python.exe scripts\verify_suspicious_segments.py
.\app\backend\.venv\Scripts\python.exe scripts\verify_growmate_real_asr.py
.\app\backend\.venv\Scripts\python.exe scripts\verify_speech_coverage_accuracy.py --window 10

powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/_sapi_render.ps1 -Voice 'Microsoft Huihui Desktop' -TextFile data/benchmark/coverage_zh.txt -Out data/benchmark/coverage_zh.wav
.\app\backend\.venv\Scripts\python.exe scripts\verify_speech_coverage_accuracy.py data\benchmark\coverage_zh.wav --language zh --reference data\benchmark\coverage_zh.txt
```

`rg` 用于定位相关代码，`Get-Content` 用于读取证据，`git diff --check` 检查修改格式。`unittest` 检查确定的程序行为；`verify_*` 使用已有样本或合成样本验证实际流程。运行真实模型的脚本设置 `HF_HUB_OFFLINE=1`，仅使用已有缓存。沙箱无法启动项目解释器或 SAPI 时，通过批准的沙箱外执行完成测试，未另装 Python 或驱动。

## 验证结果与边界

- 八项新增回归通过；原有十六项 GrowMate 测试通过。
- 停止排空专项通过：五秒已采集音频全部进入识别，十次模型调用，无输入队列丢块。
- 可疑结果分类专项通过：明确的静音幻觉仍判为 `drop`，普通中英文仍为 `keep`，不确定结果为 `retry` 并保留核对标记。
- 英语已有样本的一轮配置对照：旧配置约 29.30 秒，新配置约 14.47 秒；“Alice 起草更新预算、Bob 审核招聘计划”的句子在新配置中更完整。两组输入队列丢块均为零；这不是字符准确率统计。
- 中文合成样本最终对照：旧配置 25.43 秒，字符错误率 0.2558；新配置 18.72 秒，字符错误率 0.0349；两组输入队列丢块均为零。字符错误率按项目 `asr_metrics.py` 计算，去除标点但未统一简繁，所以改善的一部分来自简体提示。新结果仍有“清除/清楚”“圣语/剩余”等错字。
- 不将单段合成音频的结果推广为真实课堂准确率。此次修复消除了已复现的软件漏句路径，无法补回历史上没有保存的原始音频，也不保证模型不再识别错误。
- 连续讲话时最多积累约十秒音频，再加模型处理与排队时间；有静音停顿时可提前提交。这是用更完整的上下文改善识别的取舍，不承诺逐字即时显示。
- 没有中断用户正在进行的录音，没有上传原音频，没有安装驱动。日志中的实际声卡不连续仍需在后续使用中观察，本次未做长时间声卡录制验证。

## 使用方式

服务已重启。刷新 GrowMate 网页后即可开始新录音；中文课程选择“中文”，网课选择“系统声音”。结束时点击保存并等待处理完成。“建议核对”表示这句话被保留但模型信心不足；出现采音/识别错误时，页面和导出文档都会保留已记录的提示。
