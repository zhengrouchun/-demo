# 解决实时转写结束后模型持续占用内存的问题

日期：2026-10-02。范围：新增 GrowMate 本地网页版，原桌面版的缓存策略未据此宣称改变。

## 问题与原因

用户希望停止识别、导出文字后释放模型内存，继续使用其他页面。现有 `meetingbro/main.py` 的生命周期把适配器放在 `app.state.asr`，会话引用它。停止会话停止了采音和计算，但服务仍持有模型，底层库也可能缓存内存。垃圾回收无法保证所有 Python、PyTorch 或推理库内存立刻交还系统。

也不能直接杀掉正在识别的任务：停止前的音频可能仍在队列、VAD 或识别处理中。必须先排空、保存，再结束识别进程。

## 阅读并使用的文件

- `需求文档完整版V1.0.doc`：GrowMate 产品需求；平台以用户最新“先做网页版”为准，文档内 Android 阶段提示词不作为本次指令。
- `app/backend/meetingbro/main.py`：适配器创建、`app.state.asr` 与生命周期，定位长期持有模型。
- `asr/faster_whisper_adapter.py`：复用 `ensure_loaded` 与识别接口。
- `session/manager.py`：复用采音、暂停、继续、停止与尾部排空，核对事件 payload 是字典。
- `audio/`：麦克风、系统回环、混合采音。
- `app/backend/meetingbro/storage/db.py`：逐段文本持久化。
- `scripts/verify_stop_drain.py`：停止时积压不丢失的回归验证。

## 流程与方法

1. `growmate/web.py` 做轻量本地服务，不在主进程导入识别模型库。
2. `voice.py` 用 `multiprocessing.get_context('spawn')` 每次创建识别子进程。WebSocket 只订阅，不拥有录音生命周期，刷新后能重连。
3. `voice_worker.py` 在子进程内加载 NumPy、VAD、Whisper，就绪后采音。复用会话管理，关闭总结/翻译分支，转文字无需 Groq。
4. 结束时发 `stop`，会话先停采音、排空、提交文字，发完成事件，关闭存储并退出。
5. 主进程确认退出，读已保存的完整文字，由 `transcript.py` 导出时间戳 Markdown，显示资源释放。Windows 回收子进程的模型与缓冲内存，不需“清理 CPU”。
6. 导出失败保留数据库供重试；意外退出恢复已落盘文字。加载阶段未采音，可取消加载。

实现中还解决两个卡点：事件 payload 本来就是字典，直接传字典，不调用不存在的 `model_dump`；SQLite 连接上下文只管理事务，改用 `contextlib.closing` 关闭临时连接，避免 Windows 数据库与临时目录被占用。

## 指令与结果

在 `LocalLecture`：

```powershell
.\app\backend\.venv\Scripts\python.exe -m unittest discover -s tests -p test_growmate.py -v
.\app\backend\.venv\Scripts\python.exe scripts\verify_stop_drain.py
.\app\backend\.venv\Scripts\python.exe scripts\verify_growmate_real_asr.py
.\app\backend\.venv\Scripts\python.exe scripts\verify_growmate_browser.py
```

在 `app/frontend` 执行 `npm.cmd run build` 做 TypeScript 与打包校验。用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\start-growmate.ps1 -NoBrowser` 验证启动，访问 `/health`，再带 `X-GrowMate-Request: 1` 请求头调用 `/api/shutdown` 验证退出。`-NoBrowser` 仅供验证。

16 项测试通过，停止回归处理 5 秒缓冲。真实 Small/CPU/int8 识别 22.5 秒样本、保存 5 段、退出码 0、资源释放 true，未生成原始音频。一次识别进程峰值约 814.4 MB，控制进程约 24.9 到 27.6 MB。浏览器和服务仍需内存，下次识别重新加载；强制关机无法恢复内存音频。长期课堂与实际采音还需使用验证。
