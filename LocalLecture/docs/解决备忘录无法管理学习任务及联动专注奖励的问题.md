## 1. 问题、原因与最终效果

原来的备忘录以 `notes.markdown` 保存正文，已有轻量 Markdown 渲染和基础勾选，但缺少任务身份、标签、日期、进度筛选以及和专注记录、水滴流水的关联。仅凭任务文字或行号绑定属性，遇到重名、编辑或插入正文就容易关联错误；只在前端发奖励则容易重复领取。

本次沿用 React、FastAPI、SQLite、现有专注计时器及水滴/树成长系统，补齐以下功能：

- 标准 `- [ ]` / `- [x]` 显示为真实可点击 checkbox；完成文字变淡并加删除线，再次点击恢复。
- 勾选直接修改当前 Markdown 的标记并保存到 SQLite，刷新和切换备忘录后保留。
- 进度使用整份备忘录的任务数；2/7 显示 29%，无任务时不显示进度面板。
- “显示已完成”、原始顺序/未完成优先、标签筛选只影响预览；不会删任务或重排原正文。
- 每条任务有独立 UUID、标签、截止日期和累计专注时间。标签/日期可在任务右侧“标签 / 日期”中编辑。
- 任务可使用现有普通专注；专注页面也可选择任务并使用原番茄钟或严格模式。
- 专注结束后提供完成任务或保持当前状态的选择，不自动勾选。
- 任务首次完成 +1 水滴；有效任务专注在原奖励上额外 +1 水滴，复用原库存和森林浇水。
- 完成状态有约 200ms 的轻微视觉过渡；隐藏或排序更新延迟 250ms。
- 导出 ZIP 继续包含 Markdown 和图片，新增 `tasks.json` 保存任务属性快照。

新建、标题、正文、保存、切换、图片、导出、养胃记录、心情日记、实时转文字入口继续保留；桌宠人物和动作素材没有修改。本次没有更换框架或增加依赖。

## 2. 日常操作手册

1. 打开 <http://127.0.0.1:8876/>，按 **Ctrl+F5** 加载新页面。
2. 进入“记录 → 备忘录”，选已有备忘录或点击“新建备忘录”。
3. 在 Markdown 正文中输入下方示例，点击“保存备忘录”：

~~~markdown
# 学习计划

- [ ] 外部中断
- [x] GPIO基础
- [ ] OLED屏幕显示

## 今日知识点

TIM2 可以产生周期性中断。

```c
HAL_TIM_Base_Start_IT(&htim2);
// 代码块中的 - [ ] 不会变成任务
```
~~~

4. 在预览区勾选任务。正文相应位置会变成 `- [x]`，出现“任务状态已保存”；再次勾选恢复 `- [ ]`。勾选、保存任务信息和开始任务专注都会保存当前标题、正文修改。
5. 在进度面板关闭“显示已完成”可隐藏完成项；重新打开恢复。选择“未完成优先”可把未完成项放在预览上方，正文实际顺序不变。
6. 点击某条任务的“标签 / 日期”，选择常用标签或输入逗号分隔的自定义标签；选择今天、明天、自定义日期或无日期，再点击“保存任务信息”。
7. 在“按标签筛选”中选择标签，仅筛选当前备忘录任务；普通标题、段落和代码仍显示。进度仍统计整份备忘录。
8. 设置“任务专注（分钟）”，点击任务右侧“▶ 开始专注”。会保存当前备忘录并进入原“专注”页。已存在计时器时不启动第二个。
9. 若要使用番茄钟或严格模式，从“专注”页选择模式和“绑定学习任务”，再开始。重名任务在下拉项中包含备忘录标题和第几条，实际绑定独立 ID。
10. 完成倒计时后查看“最近一次专注”，选择“完成任务”或“继续保持未完成”。已完成的任务显示“保持当前状态”。返回备忘录可看到累计时间。
11. 水滴进入原库存；到“森林”执行原来的浇水操作，消耗水滴并增加树成长值。
12. 编辑普通正文、增删任务后仍需点击“保存备忘录”。保存失败时保留本地草稿；处理错误后重试，不要清空浏览器存储。多页面编辑冲突时，先复制当前正文，再重新打开该备忘录核对合并。

普通 `1. 内容` 和 `- 内容` 仍是普通列表，不会自动转换成任务。要勾选时请改写为 `- [ ] 内容`。代码围栏及四空格/Tab 缩进代码内的标记不参与任务统计。

## 4. taskId 设计及 Markdown 同步

每条任务使用 32 位小写十六进制 UUID。前端用 crypto.randomUUID，后端兼容旧调用时用 uuid4。数据库 `note_tasks.id` 为主键；任务文字和行号均不是身份标识。

前端编辑时用 `reconcileTasks` 匹配原任务并保留 ID，保存时发送 `task_links: [{id, line_index}]`。后端校验 ID、源行、数量、唯一性及所属备忘录，然后由 Markdown 解析 completed。ID 在刷新、反复勾选、普通任务文字修改后保留，重名任务仍分别有不同 ID。

checkbox 使用真实源行的标记偏移，只替换 `[ ]` 中的空格与 `[x]` 中的 x，不删任务、不改其他正文、换行和排序。表单提交的正文及 metadata 同步、首次奖励流水在同一个数据库事务中提交，出错回滚。

旧数据没有 metadata 时会在迁移中生成；旧 API 不传 task_links 时，后端按文本与位置做兼容匹配。正文中删除某条任务并保存后，删除该备忘录中不再出现的 metadata；历史专注记录和奖励流水保留，防止丢失已发生的历史。

存在一个纯文本限制：同时批量删除、重命名或移动多条完全同文的任务时，Markdown 本身不能说明哪条是原来哪条。系统按顺序和位置尽力匹配；普通勾选、刷新和逐条改名已验证稳定。需要区分身份时，建议先改成不同任务名称再批量移动。重复文字本身不会导致共用 UUID。

## 5. 标签、日期、专注时间保存位置

全部实际业务数据保存于 `data/growmate/growmate.db`，沿用现有 SQLite 文件：

- `notes.markdown`：原 Markdown 正文及完成标记，其他原字段继续保留。
- `note_tasks`：id、note_id、line_index、text、completed、tags、due_date、首次完成处理标记和时间戳。
- `tags`：JSON 数组；去空格和重名，最多 12 个，每个 1—30 个字符。
- `due_date`：`YYYY-MM-DD` 或 NULL，后端验证真实日期；显示今天、明天、月日或逾期，已完成任务不突出逾期。
- `focus_sessions.task_id`：实际任务 ID，同时保留 task_note_id 和任务标题快照 task_text。
- `focus_seconds`：从该 taskId 所有已结束专注的 actual_seconds 求和，不受页面最近 100 条历史限制。
- `water_transactions`：全部原奖励、任务奖励及浇水扣除使用同一流水；余额沿用原求和逻辑。

浏览器 localStorage 只保存现有草稿和新增显示偏好，业务属性不是仅存在浏览器内存。显示偏好键为 `growmate.note-task-view`，草稿继续使用 `growmate.note-draft`。清除浏览器存储不会清空已保存 SQLite 数据，但会丢失未保存草稿与显示偏好。

API：

- 原 `POST /api/notes`：增加 task_links、base_updated_at，返回 id 和已保存 note。
- 原 `GET /api/state`：notes 中增加 tasks，专注结果增加任务引用。
- 新 `PATCH /api/notes/{note_id}/tasks/{task_id}`：保存 tags 和 due_date。
- 原 `POST /api/focus/start`：增加可选 task_id。
- 新 `POST /api/focus/{session_id}/task-decision`：显式 completed=true/false，一次确认后重复调用返回原决定。

## 6. 复用专注与水滴/树成长

使用同一个后端 timer 设置、deadline 和 focus_sessions。任务按钮不会创建另一套业务计时器。普通、番茄钟、严格模式可绑定；番茄钟各轮沿用同一 taskId，各轮 sessionId 不同。

专注结束只累计时间和发放合法奖励。点击“完成任务”后才通过绑定 taskId 定位原任务并修改正文。任务已删除时不能完成该任务，但专注历史仍保留，可以选择保持状态。提前结束会记录实际时间，不能获得完成专注奖励。

沿用原有效条件：按计划完成且时长不少于 10 分钟。原奖励 10/25/45/60/90 分钟分别为 2/6/12/18/30 滴，其余按原规则比例处理。绑定任务后额外 +1，因此有效 25 分钟任务专注为 6+1=7 滴；若之后首次完成任务，再 +1 滴。

防重复措施：

1. 每个任务记录 completion_rewarded；原先已经完成的旧数据在迁移中作为已处理基线，不补发历史奖励，也不改变旧余额。
2. 任务完成流水类型 task_completion_reward，以 taskId 为 source_id，数据库有唯一索引。取消后再次完成不会重复发。
3. 专注额外流水 task_focus_bonus，以 sessionId 为 source_id，数据库有唯一索引；专注结算还检查 ended_at。
4. 完成状态、标记、流水事务提交，API 不接受客户端自称奖励已领取或直接设余额。
5. 专注结束决定存入 task_decision；重复决定不会重新完成或发奖励。

完成任务不会自动给树浇水。奖励进入原库存，用户仍从原森林页浇水，成长规则继续沿用。本项目已有真实库存和树成长，本次接入已验收，无须伪造或预留第二套余额。
