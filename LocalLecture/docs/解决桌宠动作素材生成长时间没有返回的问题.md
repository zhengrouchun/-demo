# 解决桌宠动作素材生成长时间没有返回的问题

日期：2026-10-03。

## 问题与原因

桌宠主图生成成功，但带本地图片路径的动作编辑请求长时间未返回，批量和单张尝试均没有得到新素材。可以确认请求未完成，但无法确认生成服务端的具体原因，不能据此断言文件损坏或 Windows 路径不受支持。

## 解决流程

1. 查看 `public/pet/gushiye/idle.png`，确认主图存在并能显示。
2. 阅读 imagegen 技能的透明背景、生成与编辑、项目素材保存要求，使用内置工具，不安装或切换到需要用户 Key 的 CLI。
3. 停止长时间挂起的请求，改用完整统一的角色描述重新生成各动作，明确画布、身体比例、服装和站位。
4. 新建眨眼请求成功返回，随后生成其他动作，每种动作独立请求，保存全部七张 PNG 到项目。
5. 检查发现现有后端环境没有 Pillow；未为此安装依赖。新增 `scripts/verify_desktop_pet_assets.py`，用标准库 struct/zlib 读取 PNG 的 alpha 通道并检查透明区域与画布一致。该脚本只检查，不修改图片。
6. 重新构建前端，用独立 Chrome 配置和临时数据库验证真实素材切换及缺图回退。

## 文件与方法

- `imagegen/SKILL.md`：内置工具、透明背景、保存项目副本的要求。
- `public/pet/gushiye/`：七种状态的最终 PNG；`README.md` 保存角色提示词和替换方法。
- `petConfig.ts`：状态到图片路径的映射。
- `petAssets.ts`：核心图片异步预加载及缺图回退。
- `scripts/verify_desktop_pet_assets.py`：PNG 签名、尺寸、alpha 解码和透明区域检查。
- `scripts/verify_desktop_pet_browser.py`：用真实浏览器检查状态与缺图回退。

使用内置 `image_gen__imagegen` 与 `transparent_background: true` 生成；`Copy-Item -LiteralPath ... -Destination ...` 保存项目副本；执行：

```powershell
.\app\backend\.venv\Scripts\python.exe scripts/verify_desktop_pet_assets.py
.\app\backend\.venv\Scripts\python.exe scripts/verify_desktop_pet_browser.py
```

生成式各动作的服装细节仍有小差异，未宣称逐像素一致；尺寸和透明背景另外验证，未来可直接换严格同模绘制的素材。
