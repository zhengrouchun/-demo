# 解决备忘录任务无法勾选和保存的问题

日期：2026-10-03（Asia/Shanghai）。

## 问题及原因

“我的记录 → 备忘录”已有 Markdown 正文、预览、保存、图片和导出功能。原预览可以识别 `- [ ]` / `- [x]`，但 `components.tsx` 的 checkbox 使用 `readOnly`，没有变更回调；`Records.tsx` 仅给 Markdown 传正文，没有把勾选关联到编辑和保存。完成任务也没有专用文字样式。

后端已经支持以同一个备忘录 ID 更新 Markdown，故无需新增数据库表、转换旧记录或迁移正式数据。

## 阅读与使用的文件

- `app/frontend/src/growmate/Records.tsx`：Records 找到“我的记录”的 notes Tab；Notes 找到正文 textarea、localStorage 草稿、保存、切换、图片和导出。修改仅限 Notes 和相关 import。
- `app/frontend/src/growmate/components.tsx`：Markdown 的只读 checkbox、逐行 Markdown 渲染和 inline 粗体/行内代码。保留普通文本、标题、列表、引用、图片及 React 文本转义，添加勾选回调。
- `app/frontend/src/growmate/GrowMate.css`：沿用现有 checkbox 尺寸和主题色，只增加任务文字完成样式与多行对齐。
- `app/frontend/src/growmate/api.ts`：沿用 api 的请求头和错误处理；没有修改。
- `app/frontend/src/growmate/GrowMateApp.tsx`：确认 run 操作成功后刷新 /api/state，出错展示全局提示；没有修改。
- `app/frontend/src/growmate/types.ts`：确认 Note 的原字段与 ViewProps.run 签名；没有修改。
- `app/backend/meetingbro/growmate/repository.py`：notes 表的 markdown 字段、state 的读取和 save_note 的 UPDATE，保留原 created_at，仅更新正文/标题和 updated_at；没有修改。
- `app/backend/meetingbro/growmate/web.py`：POST /api/notes 保存、独立 DELETE 删除，以及 Markdown＋图片 ZIP 导出。确认导出会转换图片相对路径；没有修改。
- `app/frontend/package.json` 和现有验证脚本：确认 TypeScript、构建、Node 和独立 Chrome 测试工具；没有安装新依赖。

## 解决流程与方法

1. 新增 `app/frontend/src/growmate/markdownTasks.ts`。markdownLines 让渲染与编辑共用任务识别规则，只将实际的 Markdown 任务行识别为任务；三反引号、波浪线围栏和缩进代码中的任务示例保持代码。
2. setMarkdownTask 按点击的源行定位，仅把标记的一字符从空格换为 x，或从 x/X 换为空格。任务文字、行数、重复任务、图片、其他内容、CRLF 和空格均保留。
3. Markdown 的 onTaskToggle 传回源行和勾选值。已完成文字添加 completed 类，显示灰色、降低透明度和删除线；取消勾选恢复。
4. Notes.toggleTask 同时更新 textarea 和预览，再用原 POST /api/notes 保存当前标题与全文。旧记录使用原 ID，新草稿首次勾选可直接创建记录。
5. withSaving 使用 ref 即时防重入，并在保存期间暂时锁定当前备忘录的编辑、切换、删除和复选框，避免交叉保存覆盖。请求失败保留勾选后的本地草稿与“未保存”状态，用户可点击保存重试。
6. save(snapshot) 使用本次实际更新后的正文；即使保存过程中切到其他 Tab，也会为匹配的本地草稿记住新 ID。不会把返回结果写到另一份已经改过的草稿。
7. 旧备忘录不自动转换：普通数字列表、正文与普通列表继续按普通内容显示。勾选从未调用删除接口；原删除按钮仍是独立操作并要求确认。

本次新增 `scripts/verify_note_tasks.cjs` 与 `scripts/verify_note_tasks_browser.py`。另外仅修改上述 Records.tsx、components.tsx、GrowMate.css；实时转写、桌宠素材/代码、AI、健康与心情模块保持原内容。

## 验证中遇到的问题

首次浏览器测试在按中文 aria-label 查找 checkbox 时失败：先用默认 json.dumps 生成了包含字面量 \\u 的 CSS 选择器，外层再次编码后，CSS 无法匹配实际中文名称。将内层改为 `json.dumps(label, ensure_ascii=False)`，实际功能代码无需改动。

第二次测试的导出断言失败：测试误以为 ZIP 内的 Markdown 仍保留 /api/images 地址。读取 web.py 的 download_note 后确认，原设计会将它转换为 images/文件名，方便离线查看。修正测试预期，并验证 ZIP 内图片字节与上传原图一致，没有修改导出功能。

两处验证问题修正后，完整浏览器检查通过。

## 使用方式

刷新 http://127.0.0.1:8876/（必要时 Ctrl+F5），进入“记录 → 备忘录”，在正文中输入：

```markdown
# 学习计划

- [ ] 收到后端的资料，开始测试搭建测试电路
- [ ] 数码管显示（基础）
- [ ] 数码管显示（进阶）
- [ ] 按键控制
- [ ] 外部中断
- [ ] OLED屏幕显示（上）
- [ ] 整理知识点

## 今日知识点

TIM2 是 STM32 的通用定时器。
```

在下方“预览”点击复选框会自动保存当前备忘录（包括当前尚未保存的标题和正文修改）；再次点击取消完成。单独编辑正文仍使用“保存备忘录”。若提示保存失败，草稿仍保留，恢复连接后点击保存即可。

完成的任务不会从备忘录消失，导出也保留其 Markdown 状态。本次保存当前任务完成状态，尚未添加今日/每周统计或完成时间事件记录。
