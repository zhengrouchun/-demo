# Design

## Context

动机见 `proposal.md`。用户已明确选择当前 Windows 电脑的麦克风上课时持续转写；课后文件导入不在本次范围。现有需求以普通话、夹杂英语术语为主，本设计沿用该语言范围。未把用户未承诺的零错字、远场距离或硬件性能写成已实现事实。

### 已读文件与直接证据

- `Windows离线课堂转写准确率与功能需求.md`：首版被收窄为系统声音，要求离线免费、不保存整课原音频、排空后导出。此次明确扩展麦克风；旧“无麦克风入口”的限制在实现时更新，其他约束继续适用。
- `LocalLecture_PRD_V1.0.md`：现实课堂故事原本就是笔记本麦克风采音；记载目标电脑为 Core Ultra 5 225H、32 GB 内存，实际配置与性能在实机验收时核实。
- `src/growmate/Voice.tsx`：`systemOnly` 隐藏来源和麦克风，且把开始请求固定为 `system`、`funasr-nano-gguf-q8_0`、`zh`；`GrowMateApp.tsx` 的专用入口传入此限制。
- `growmate/voice.py` 的 `start`：已支持 `mic/system/mixed`，但明确拒绝 Fun-ASR-Nano 非系统声音组合；不能只改前端。`_event`、`_pump` 已有文字及错误落库、导出和进程回收能力。
- `growmate/voice_worker.py`：引擎和音源分别创建，已有 `MicrophoneSource`；停课使用现有 graceful drain。`audio/capture.py` 中麦克风固定以 16 kHz 单声道打开，队列满有计数，但输入回调 `status` 只记 debug 日志；这些是新场景输入兼容和漏音可见性的具体改动点。
- `audio/devices.py`、`growmate/devices.py`、`growmate/web.py`：现有子进程枚举输入设备，接口为 `/api/audio/devices`；`VoiceInput` 已有 `audio_device` 字段，可保留请求格式。
- `growmate/transcript.py`：已有麦克风来源中文映射、实际模型与错误提示导出；`growmate/types.ts` 中统计字段可兼容扩展。
- `asr/funasr_cli_adapter.py`：本地可执行文件与 GGUF 权重、16 kHz 输入、短窗临时 WAV、SRT 段落时间戳已接入；还存在网络术语替换，不能无条件推广到所有课堂。现有固定置信值也不能解释为真实准确率。
- `scripts/score_classroom_transcription.py`：底层可计麦克风分数，但 `evaluate_transcripts` 强制必须有系统声音参考，当前无法独立运行仅麦克风验收。`tests/test_score_classroom_transcription.py` 覆盖现有系统与双来源行为，应保留。
- `tests/test_growmate.py`、`scripts/verify_growmate_real_asr.py`：已有模拟与文件回放测试，并明确不打开真实麦克风；不能用其替代实机测试。`scripts/verify_growmate_browser.py` 可扩充专用页面操作验证。后端 `pyproject.toml` 和前端 `package.json` 给出了现有依赖、pytest 与构建方式。
- `系统声音模型候选未完成长时验收的原因.md`、`Windows系统声音逐字稿启动与操作说明.md`：系统声音样本曾测得 Fun-ASR-Nano 3.01%、Whisper Small 10.89%，但真实回环约 14 分钟出现异常，60 分钟验收未通过。这些仅是已有系统声音证据。
- `openspec/config.yaml` 采用 `spec-driven`，无额外 context；主规格为空。当前开发分支已有 1 个未推送提交与用户的未跟踪术语文本，均须保护。

以上路径在未写全前缀时，前端位于 `LocalLecture/app/frontend/`，后端位于 `LocalLecture/app/backend/meetingbro/`。本轮仅创建 OpenSpec 规划文件。

## Goals / Non-Goals

**Goals:**

- 在已有架构内串通专用入口、真实麦克风、已接入识别引擎与持久化逐字稿，避免维护第二套会话流水线。
- 对用户展示采集是否就绪、是否听到声音、是否积压及是否发生漏音；诊断与识别分开验证。
- 为麦克风单独制定可执行的质量、离线和完整性门槛，交付结论建立在实测结果上。

**Non-Goals:**

- 不重构系统声音、混音、GrowMate 其他页面或原会话管理器，不修复已知但根因未明的回环故障。
- 不新增推理框架、GPU/NPU 路径、自动降噪、自动增益、领域词表或新的硬编码术语替换。诊断显示电平，不自动放大噪声。
- 不把模型宣传指标、输入电平或固定置信值包装成课堂识别准确率；不为此开发驱动或 CubeMX 工程。

## Decisions

### 1. 复用本地链路，按场景限制来源

采用既有 `MicrophoneSource → TranscriptSession → ASRAdapter → SQLite → Markdown`。专用入口把 `systemOnly` 表达的旧限制替换成明确的课堂模式：系统声音和麦克风，不在专用入口开放 mixed；默认仍是 system，旧启动脚本与 `?transcript` URL 保持可用，页面标题调整为“课堂声音转文字”。原 GrowMate 的完整来源选择和 Whisper 选项保持原行为。

备选是只让用户去旧 GrowMate 的麦克风页，但它绕开了专用入口的较高质量模型与诊断；另一备选是重建课堂应用，重复了存储、会话和界面。云端方案不满足本地、无 API 费用的约束。因此本设计在现有链路上做定向扩展。用户确认的是现场麦克风场景；具体模块安排和下述门槛是本提案供审阅的设计建议。

### 2. 引擎复用与准确率门槛

优先试验现有 Fun-ASR-Nano GGUF Q8_0 及 Windows CPU 程序；以原 Whisper Small CPU int8 麦克风配置建立同一音频基线。`voice.py` 仅增加允许该 FunASR 模型与 `mic` 的组合，继续拒绝未经范围确认的 FunASR mixed，不改旧模型或旧历史。

保留现有 30 秒积累／窗口设置作为麦克风起点，准确和完整优先；首次确认文字通常有几十秒延迟，不承诺即时字幕。只在代表性样本证据支持时调整麦克风独立配置，不连带改变系统声音参数。麦克风模式关闭现有网络领域专用的输出替换，保存模型输出；将控制项做成适配器的可选参数，旧系统声音默认行为保留。它不是新的润色流程。

选用模型前分别验证：本地资产齐全、正确采样率、窗口顺序与尾段、断网运行、真实课堂文字与处理速度。没有候选达标时停止正式交付，报告证据并讨论；禁止静默回退后仍显示 FunASR 或标记已通过。

质量评测读取用户提供或在后续单独确认的课堂样本，至少合计 10 分钟，覆盖实际座位到老师的距离、典型噪声、正常停顿与课程术语；同一音频、同一人工稿供两个引擎识别。按现有 NFKC、casefold、去标点与空白规则计算 CER（字符编辑距离／参考字符数）。建议的交付门槛为 CER ≤ 10%，且 ≤ 基线 × 90%；若基线为 0，候选也须为 0。漏掉的完整句子与专业术语错误分别人工计数且不得多于基线。该门槛待本提案确认后生效，不是已有测试结果或任意环境的准确率保证。

评分工具增加仅 `mic` 输入支持，保留 system-only 与旧双来源格式。新增按来源的 `cer_gate_passed`，麦克风再给出绝对门槛结果；旧 `mean_cer` 与旧总体门槛语义保持兼容，不能以双来源平均值代替麦克风通过。基线为零只用于新来源门槛的等零判断，保留旧总体结果中基线为零不算相对提升的约定。漏句、术语人工核对记录独立保存，自动 CER 不能给它们代签通过。

### 3. 麦克风检测与就绪信号

沿用 `/api/audio/devices`。新增 `POST /api/audio/microphone-check`，请求只接受 `audio_device`，运行固定 5 秒，返回设备名称、实际采样率、RMS／峰值 dBFS、削波比例与提示；不返回音频或正文。默认设备在操作开始时解析一次，指定设备失效就报错，不能无声替换。检查使用短生命周期子进程，10 秒硬超时；完成、请求取消或服务退出均在 finally 关闭输入流并回收进程。

建议拆分 `growmate/microphone_check.py`（子进程协议、输入检查及错误归类）与 `audio/microphone_health.py`（纯电平计算和可测试阈值），由 `web.py` 做薄路由。通过控制器已有锁及检测占用标记，互斥正式转写与检查；原有活动会话也禁止检测占用，不只由前端按钮防重入。

打开前使用设备查询和 `check_input_settings` 验证输入声道、采样率及设备。优先沿用 16 kHz；仅当明确得到采样率不支持时，尝试该设备报告的默认采样率，再以现有 scipy 重采样工具转为 16 kHz 单声道供 ASR。其他打开错误直接报告，不能泛化重试。兼容路径只作用于本次麦克风配置，旧调用保持默认；44.1／48 kHz 用音频时长与相邻块连续性测试验证，不添加新音频库。

正式课程只有输入流成功打开并开始接收后才能显示采音就绪；模型加载和音频准备时仍显示准备中。适配现有 session_state 时避免其过早覆盖音频准备状态。打开失败记录实际异常，不把权限、设备占用或驱动问题中的某一个猜成根因。若确实需要厂商驱动或硬件资料，再向用户索取，不自行编写或安装。

### 4. 输入电平和错误沿现有事件通道传递

回调只汇总计数和电平，不执行 ASR、文件写入或网络操作；聚合状态最多每秒一次经 worker 和现有 voice snapshot 发送。新增可选统计字段为 `mic_rms_dbfs`、`mic_peak_dbfs`、`mic_clipped_ratio`、`mic_low_input_seconds`、`mic_input_overflow_total` 和 `audio_capture_state`，旧页面不要求这些字段。

初始诊断阈值采用具名配置：低输入 RMS < -50 dBFS 连续 10 秒时提示；绝对幅值 ≥ 0.99 的样本比例 ≥ 1% 时提示削波；无信号以接近数值零区分。阈值仅用于提醒，不能推断老师是否说话或准确率是否达标，具体阈值可由实现者结合样本校准并记录。暂停时不累计低输入时间，暂停音频不进入识别；继续后时间戳沿现有有效采音时间递增，不增加新的墙钟时间语义。

把 sounddevice 的 input overflow 从仅 debug 日志升级为可累计的完整性告警，与应用音频队列丢块分开计数，避免重复相加。采集状态异常、溢出或丢块写入当前课程已有 error 字段并显示持久提示；采集致命终止使用 interrupted，不让 worker 正常退出代码掩盖采音失败。已有正文保留，能够处理的队列安全收尾；不可确定的尾段明确提示缺失。后续正常状态事件不得抹去此前完整性告警。不自动切设备、不重启后当成一堂无损课程。

### 5. 数据、离线与临时音频

复用现有 voice_sessions、transcript_segments 和 `data/growmate/transcripts/`；来源使用已存在的 `mic`，实际模型记录沿用原模型名，不做数据库迁移。若需要让页面持久显示设备名称，首先通过当前会话快照传递，不擅自新增历史列。历史以模型字段及来源显示事实。

只保存文字及必要诊断汇总。FunASR 现有短窗 WAV 在自有 `data/funasr-temp/locallecture-funasr-*` 中产生，正常异常路径均清理；启动时只在已确认没有活动 worker 的条件下清理该根目录内本应用遗留的临时子目录。解析每个实际路径、拒绝重解析点及越界路径，保护其他文件和活动会话。禁止保存整课 WAV、自动生成录音备份或提交样本／模型／图片／音视频。

首次准备可需要下载开源模型和运行程序；使用阶段无 API、订阅或按量费用，不包含用户的电费、网络或可选硬件成本。正式启动只用本地资产，缺失时给出准备说明；Whisper 对照运行也设置离线加载，防止测试偷偷下载。真实断网测试验证完整流程，清空 API Key 后仍工作。保留既有禁用总结／翻译的会话实现。

### 6. 测试与模块边界

后端在既有测试中加入麦克风模型组合、活动互斥、采集就绪、检测超时和释放、采样率兼容、溢出告警持久化、尾段排空与恢复；输入指标用合成 PCM 和替代输入流验证。前端复用已有浏览器检查脚本的临时数据和 Chrome 调试机制，验证来源选择、设备显示、状态锁定、异常与旧入口；不只检查源码字符串。

自动化文件回放只验证识别和存储链路。真实麦克风验收单独执行：短时输入和真实课堂样本、断网流程、连续 60 分钟采集及结束后 10 分钟导出、十分钟后强退重启、静音和禁用设备场景。记录时长、丢块、溢出、积压峰值、导出耗时、输出段数、状态与进程释放；不在测试日志公开课堂正文。长时稳定测试不保存整课音频，准确率评测用用户单独提供的代表性短样本。

新增代码按输入诊断、会话控制、UI 和评测归入对应模块，使用能表达作用的名称及具名阈值；只改动本功能相关代码。关键新增／修改语句逐条作用说明写入后续《解决现实课堂麦克风无法在专用页面转写的问题.md》，结合根因、读取的文件位置和真实命令结果；不把本规划冒充已解决报告。

## Risks / Trade-offs

- [远距离、混响、多人同时讲话与噪声导致不可恢复的信息损失] → 课前检查输入、选择正确设备与摆放位置，以真实课堂样本判定；不足时先报告，不承诺软件能还原听不清的音频。
- [准确率目标可能无法由现有免费模型达到] → 两个已有引擎在同一麦克风样本对比；不达标就讨论，功能可运行不等于质量交付。
- [CPU 负载与 30 秒窗口增加等待和积压] → 明确预览／确认文字差别，复用积压告警，以 60 分钟和结束耗时判定；不为低延迟牺牲尾段。
- [设备采样率、权限、禁用或驱动异常] → 输入格式预检、限于采样率错误的兼容路径、保留实际异常；需要外部驱动时请用户提供。
- [新诊断影响既有麦克风或混音调用] → 诊断与兼容配置仅对新课堂路径启用，默认接口行为保持；增加旧路径回归验证。
- [强退可能丢失内存中待处理尾段] → 正文自动落库并明确恢复边界，不通过保存整课原音频改变用户要求。
- [旧系统声音长课问题仍在] → 本次只做短流程回归，不把麦克风通过宣称为回环问题修复。

## Migration Plan

1. 后续用户明确启动 apply 后，先保留已有未跟踪术语文件和未推送提交，以小步实现后端组合与评测，再做诊断和 UI；本轮不安装依赖、不打开麦克风、不修改产品代码。
2. 完成功能测试和构建后进行真实样本、断网与长时验证；缺少样本或结果失败时明确标为未验收，不能把任务全部勾选。
3. 更新旧需求和操作说明，解释新增麦克风场景及未解决的回环风险。原脚本继续可用，不自动覆盖旧课程或备份。
4. 按桌面工作区的存档要求，每个小功能先展示差异和验证结果，用户确认后再 Git 提交；提交后再依项目规则检查分支和远程并推送当前非 main/master 分支。当前已有的未推送提交也会被 push 带上，提交／推送前必须明确展示范围。
5. 回滚以撤销本功能对应提交为主，不重置或清理用户工作区；无数据迁移，已保存文字继续可导出。没有 Commit 前只撤去本变更的规划文件或实现差异，不能删除整目录运行数据。
